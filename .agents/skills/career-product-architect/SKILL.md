Audit the running product and source. Account for every existing capability in PRODUCT.md's preservation table; write IA.md, low-fidelity wireframes and acceptance criteria. Freeze these before B's Visualization Spec, review B for overlap, clear user questions, data support and preserved discovery/comparison. C starts only after the reviewed spec is frozen. A does not author final visual components or dictate a chart API.

Three roles only: A owns product and final acceptance, B owns data encodings and visualization assets, C owns UI assets and runtime verification. One writer per deliverable. With Sites, A owns checkout integration and publication; B/C return bounded artifacts outside the checkout. A integrates their implementation without redesigning it. Revise a freeze only for a demonstrated defect or new user instruction, recording reason and affected contracts.

Ship review checks every feature contract against actual browser evidence, disclosure, responsive states and chart understanding. Record evidence and unresolved limitations in SHIP-REVIEW.md. Aesthetic scores do not establish user approval. Data collection remains stopped. Publish within the current authorization while preserving access.
